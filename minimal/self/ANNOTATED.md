# `self/golf.golf`, annotated

This is a human-readable listing of the self-hosted GOLF compiler. The real file
is generated by `tools/mkblob.py` (which also strips the cosmetic spaces shown
here and injects the golf abbreviations `P`/`Y`/`Z`/`L`). **Do not hand-edit
`self/golf.golf`** — it contains a raw-byte template blob; edit `mkblob.py`.

## Runtime memory map (used by the compiler at run time)

```
D = 0x410000  (word `m` pushes this)
  D+0   C   current input char        D+4   P   output pointer (write cursor)
  D+8   T   template-blob address      D+12  S   scratch (find-key / blob VA)
  D+16  Q   pushed-back char (0 = none)
  D+2048  dictionary: dict[c] at D+2048+4*c   (a 4-byte code address per word)
  B = D+4096  output buffer: file offset f is stored at B+f
```

Everything the compiler emits is built in the output buffer at `B`, then written
to stdout at the end. A target virtual address equals `bufaddr - 69632`
(`= f + 0x400000`).

## Golf abbreviations injected by `mkblob.py`

| word | expands to | meaning |
|------|-----------|---------|
| `P` | `m4+@` | fetch the output pointer |
| `B` | `m4096+` | output-buffer base address |
| `S` | `m12+` | scratch var S address |
| `Q` | `m16+` | pushed-back-char var Q address |
| `U` | `48-10<` | is-digit test core (`value-48 < 10`) |
| `Y` | `m2048+\4*+` | dictionary slot address for the key on top |
| `Z` | `48-\10*+` | fold one decimal digit into an accumulator |
| `L` | `104o` | emit the `push imm32` opcode byte (`0x68`) |

## Word definitions (in source order — define before use)

```
:m4259840;              # m : push the data-region base D (0x410000)
:P m4+@;                # P : fetch output pointer  (abbreviation)
:a m4+\&@+\!;           # a : advance P by n        [n]->[]   P += n
:o m4+@!1a;             # o : emit one byte         [b]->[]   store b at P; P += 1
:L 104o;                # L : emit push-imm opcode  (abbreviation)
:w m4+@!4a;             # w : emit a 32-bit dword   [v]->[]   store v at P; P += 4
:k "m4+@\-4-\!;         # k : backpatch — pop a site, store rel32 = P-(site+4) there
:c {\"?o1+\1-"1<}__;    # c : copy n bytes from addr to output   [addr,n]->[]
:C "1+?\2+\c;           # C : copy a template body given its record addr  [rec]->[]
:f m12+!m8+@{"?"[_^]m12+@-[^]"1+?2++0};
                        # f : find blob record for key -> its addr (stops at match
                        #     or at the 0 sentinel). key kept in S (D+12).
:E fC;                  # E : emit the template for a key        [key]->[]
:Y m2048+\4*+;          # Y : dict slot address     (abbreviation)
:Z 48-\10*+;            # Z : digit fold            (abbreviation)
:e "f"?[_232o Y@ P4+-w^]\_C;
                        # e : compile a dumb op OR a word call.
                        #     Find the char's record. If found, copy its template.
                        #     Else (0 sentinel) emit `E8 rel32` calling dict[char].
:D 0{("48-10<[_^]Z0};   # D : read a decimal number, consuming the terminator  [->n]
:g m16+@"[_(^]0m16+!;    # g : get next char: use pushed-back Q if set (clear it),
                        #     otherwise read one byte from stdin.
:h {("10-[_^]"[_^]_0};  # h : skip a comment — read until newline (10) or EOF (0)
:t ...                  # t : dispatch one token (the current char). See below.
:H 4f"1+?\2+\&+m12+!{"?m4096++&1+?\,2+"m12+@<1+}_;
                        # H : write the ELF header.  Record key 4 holds its
                        #     non-zero bytes as (offset,value) pairs; store each
                        #     value byte at B+offset over the zeroed buffer.
```

### `:t` — the token dispatcher

`t` receives the current char on the stack. It is an if-chain; each case is
`"X-[ handler ^]` — dup the char, subtract `X`, and if the result is `0` (char ==
`X`) run the handler and return. Anything unmatched falls through to `e`.

```
:t
  "33<1+[_^]                          #   char <= 32  : whitespace -> drop, return
  "35-[_h^]                           #   '#'         : skip comment line
  "48-10<1+[                          #   '0'..'9'    : number literal
     48- {                           #      seed value = char-48; then loop:
        ( "48-10<[m16+!L w^]          #        read char; if NOT a digit: push it
                                      #        back into Q, emit `push value`, return
        Z 0 }                        #        else fold digit into value, continue
  ]
  "39-[_( L w^]                       #   '\''        : char literal -> emit push c
  "58-[_( 233o P4+\ m2048+\4*+! P0w 1E^]
                                      #   ':'         : define word `name`:
                                      #     emit E9(jmp-over) + 4-byte placeholder,
                                      #     dict[name] = body addr, emit prologue,
                                      #     leave the placeholder site on the stack
  "59-[_94E k^]                       #   ';'         : emit epilogue, backpatch site
  "91-[_2E 133o P0w^]                 #   '['         : emit test + JNZ placeholder,
                                      #                 leave its site on the stack
  "93-[_k^]                           #   ']'         : backpatch the JNZ site
  "123-[_P^]                          #   '{'         : push loop target (current P)
  "125-[_2E 132o P4+-w^]              #   '}'         : emit test + JZ back to target
  "96-[_D 233o"w P69632-m12+!         #   '`'         : blob — read count, emit
        {(o1-"1<}_ L m12+@w^]         #     E9(count)+bytes copied from input, then
                                      #     `push` the data's virtual address
  e ;                                 #   otherwise   : dumb op or word call (via e)
```

Key invariant: every handler is exactly stack-neutral **except** `:` `[` `{`,
which each push one backpatch address, and `;` `]` `}`, which each pop one. The
main loop below is otherwise stack-neutral, so those pending addresses accumulate
harmlessly at the bottom of the data stack and are consumed in LIFO order — the
data stack *is* the backpatch stack.

### Main program (runs first; the definitions above are jumped over)

```
`229 <229 raw template bytes>   # push the blob address ...
m8+!                            # ... store it in T (D+8)
H                               # write the ELF header into the zeroed buffer
m4096+120+m4+!                  # P = B + 120 (code begins after the header)
3E                              # emit startup: mov ebp, 0xC00000 (record key 3)
{ g "m! t  m@1< }               # token loop: get char, save in C, dispatch;
                                #   continue while C != 0 (m@1< is 0 when C>=1)
5E                              # emit exit(0) (record key 5)
m4096+{"?)1+"m4+@<1+}_          # flush the output buffer B..P to stdout, one byte
                                #   at a time
```

## The template blob

`` `229 … `` embeds 229 raw bytes: length-prefixed records `[key][len][len bytes]`
ending in a `0` sentinel. `f` scans it by key.

| key | contents |
|-----|----------|
| 1 | word **prologue** (`sub rbp,8; pop [rbp]`) |
| 2 | shared **cond-prefix** `58 48 85 C0 0F` (used by both `[` and `}`) |
| 3 | **startup** `mov ebp,0xC00000` |
| 4 | the ELF header's **non-zero bytes** as (offset, value) pairs (written by `H`) |
| 5 | **exit(0)** |
| ASCII code of each dumb op | that op's machine-code template |

All template bytes are defined once in `boot/golf0.py` and copied here by
`tools/mkblob.py`, so the Python reference compiler and the self-hosted compiler
agree byte-for-byte — which is why the bootstrap reaches not just a fixpoint
(`stage2 == stage3`) but the strict fixpoint `stage1 == stage2`.
